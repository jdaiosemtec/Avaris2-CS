Editions (licence-controlled, one installer) — PREPARED BUT NOT ACTIVE (AV.LICENSING = false in licence.js until the user decides the licensing scheme)
- No key → OsemCM 1D (unregistered). 1D key → OsemCM 1D. 1D-2D key → OsemCM 1D-2D (2D Flood ribbon tab, 2D Options, Create Meshes, 1D-2D run, flood maps).
- Keys: `license-tools/keygen.js --edition 1D|2D --name "Licensee" [--expiry YYYY-MM-DD] [--serial S]`; signed with `license-tools/private_key.pem` (NOT in git, copy kept in releases/license). The public key is in app/main.js.

Rules
- 1D fixes requested "based on OsemCMV1.0" are made on branch `v1` (versions 1.23.x) and can be merged into `main`.
- 2D work is done on `main` only.
- Every installer that is sent out gets a tag (`v1.23.x` / `v2.0.x`) and a line in CHANGELOG below.

- v2.9.0 — Unstructured 2D mesh: Create Meshes asks Square grid (as Avaris DS) or Unstructured mesh (triangles). The unstructured mesh follows the boundary, buildings, cut-off lines, water front and new optional Break Lines exactly; new optional Mesh Zones (polygons with "size") make cells finer or coarser; sizes change gradually; about the same number of cells as the square grid for the same cell size; very small triangles merged into quadrilaterals. Same link-node engine scheme (plan area of the links = cell area exactly; Avaris DS rule for squares), so runs, coupled parallel runs, results, flood analysis, exports (shapefile, GeoTIFF/ASCII, flood extent polygons), cross sections and comparisons work for both mesh types; cell velocity = least-squares vector of the face velocities (unchanged for squares). Exclusion polygons get a type per polygon (attribute "type"): VOID (no cells), RAISED (cells raised by "height") or POROUS (area and flow width × "porosity"), with defaults in Options → 2D Flood; works for both mesh types. Mesh type, zones, break lines and exclusion defaults saved as ;;@OSEM2D lines.
- v2.9.1 — Auto Calibration opens as a large dialog over the whole window (the side panels no longer take room from it; close with × or Esc, asks to save; a running calibration keeps running and the dialog comes back when opened again). Zoom-to and pick-from-map buttons hide the dialog and show a bar at the bottom of the map to return (pick: the first object clicked on the map is taken). Results chart: the current model is drawn last (dashed, on top of the option), and when the option gives the same values as the current model at that monitor a note says so (the lines overlap). Chart legends wrap to the next row in narrow charts instead of being cut off.
- v2.9.2 — File Geodatabase feature classes of any size can be added: the layer is converted to GeoJSON Sequence and read feature by feature (before, one GeoJSON text above ~512 MB failed with "Cannot create a string longer than 0x1fffffe8 characters", e.g. a state-wide building layer). For feature classes with more than 100,000 features Add Data offers Model Area Only (features within the model extent + 15 %, using the model coordinate system) or All. Test: 2,000,000 polygons — model area 895 features in 2 s, all in 108 s.
- v2.9.3 — Create Meshes with many buildings: fixed "Maximum call stack size exceeded" (arrays of more than ~100,000 cells / lines were spread into function calls in the mesh builder, the .finp writer, the coupled-run report merge, attribute statistics and data reading). Unstructured mesh: buildings smaller than a quarter of a cell no longer shape the mesh (that needed tiny cells around each of them); they reduce the area and flow width of their cell instead (cell info "Small buildings inside: open area x %", export btype SMALL); missing constraint edges are no longer split without limit (touching or crossing building outlines). Exclusion layers from a geodatabase are read only within the 2D boundary. Square grid: exclusion polygons found through a spatial index (fast with tens of thousands of buildings). Fixed: geodatabase layers added in 2.9.2 were placed wrongly (the GeoJSON sequence is in WGS 84 longitude/latitude, now reprojected correctly). Cell Size note in Options → 2D Flood explains the size for both mesh types.
- v2.9.4 — Editing of imported vector layers as in Avaris DS: Layer View ▸ right-click a layer ▸ Start Editing (✎ in the Layer View, * when there are unsaved edits); the normal tools then work on its features: Select (click; box; Ctrl adds), the Properties panel shows and edits the attributes of the selected features (one value for all selected; + Add Field), Remove / Del deletes, Add ▸ click the layer in the Layer View ▸ draw new features, Edit Geometry drags vertices (double-click an edge adds one, right-click removes one); every change is one undo step; Attribute Table column menu ▸ Delete Field. Save Edits writes the shapefile back (only the .dbf when no geometry changed; geometry in the layer's own coordinate system); geodatabase / GeoJSON / KML layers are saved as a new shapefile. Stop Editing, Remove, opening another model and Create Meshes ask to save unsaved edits. Options ▸ 2D Flood ▸ Exclusion Layers: a table of exclusion layers (one row by default; + Add Layer..., + From Map Layers), each with its own Type (VOID / RAISED / POROUS), Height and Porosity for polygons without their own attributes; ↑ ↓ set the order (the upper layer counts where layers overlap); the first layer is stored as before (Avaris DS compatible), the others as ;;@OSEM2D EXCL_MORE. Layer View ▸ Use as Exclusion Layer... New option Buildings (unstructured mesh): LARGE (default; only buildings larger than one cell shape the mesh, smaller ones reduce the area and flow width of their cells), ALL (as 2.9.0–2.9.3: fine cells around buildings, short time steps, slow) or NONE; a building over several cells shares its blocked area among them. The run dialog shows the number of 2D cells and surface links.
- v2.9.5 — Unstructured mesh with porous cells (small buildings, POROUS): the length of a surface link is now taken from the open geometry (at least the distance between the cell centres) and porosity only narrows the link; before, porosity shortened links down to 1/4 of that distance, which with steep ground gave "elevation drop exceeds length" links and unstable runs. Test (demo model, 2,500 buildings incl. 80 large ones, 5 s step): square grid continuity −15.9 % in 1 min 37 s; unstructured LARGE +5.8 % in 1 min 59 s (the same model without buildings: square 3.3 %); unstructured ALL makes 149,000 cells and is not practical with many buildings.
- v2.9.6 — Coupled parallel run with long node IDs (e.g. DWSD "WWMH0000011693"): the sub-models were written with the coupling inflow time series CPL_Q_<node> glued to its type FLOW ([INFLOWS] "CPL_Q_WWMH0000011693FLOW 1.0 1.0"), so the engine stopped with ERROR 209 undefined object. Fixed in Partition Model (every field is followed by a space), and existing sub-models are repaired automatically at run time (a corrected copy in the run's _parts folder; the partition files are not changed). The same missing-space problem with long names is fixed wherever .inp lines are written field by field (inflows, pollutant / groundwater rows, copy & paste of objects, unit conversion, parameter editors).
- v2.9.7 — A run with an unstructured mesh made by an older version (mesh file without generator version 2) asks to rebuild the mesh first (Rebuild Mesh, then Run / Run with Old Mesh): a run only uses the saved mesh, so the 2.9.5 fix for porous cells takes effect only after Create Meshes. New meshes store gen: 2.
- v2.9.8 — Coupled parallel run of a model with USE HOTSTART (DWSD): every sub-model read the hot start file of the whole model, whose object counts differ from the sub-model, and the engine stopped with ERROR 333 (incompatible data in hot start file). The hot start file is now split per sub-model at run time (app/hssplit.js: records are matched by object ID using the order of the whole model; objects the whole model did not have — boundary outfalls, 2D cells and links — start empty with links open) and written to the run's _parts folder; SAVE HOTSTART of a sub-model goes there too. Relative paths in [FILES] of the sub-models are resolved from the partition folder. Test (RD3 Riverside, 2 sub-models, 1D-2D): initial stored volumes 0.571 + 1.796 = 2.367 ha-m = final storage of the whole-model run that saved the file; 2D results as without hot start.
- v2.9.9 — Database ▸ Delete: results files that were still open (a results file read by a comparison, flood map or earlier load keeps a handle in the main process; on Windows an open file cannot be deleted) stayed on disk because the error was ignored, and the run stayed in the list without its run information. Now the open readers of the run are closed first, a locked file is tried again a few times, files that still cannot be deleted are named in a message, and the sub-model folder <name>_parts of a coupled parallel run is deleted with the run (it is listed in the confirmation).
- v2.9.10 — Coupled parallel run: a sub-model copy written to the run's _parts folder (1D-2D sub-model, repaired CPL_Q lines, hot start) kept relative data-file paths such as "../pg_ts.dat", which the engine then looked for next to the copy (DWSD: ERROR 317 cannot open rainfall data file …\Run_…_parts\../pg_ts.dat). Relative paths of rain gage files, time-series files, [FILES] and the temperature file are now made absolute from the folder of the sub-model file. Test (RD3 Riverside 1D-2D, rain gage FILE "../rain.dat" + USE HOTSTART "../master.hsf" in the sub-models): runs, same precipitation as with the time series.
- v2.9.11 — Square 2D mesh: a manhole whose cell was removed because its centre lies in a VOID building is now coupled to the nearest kept cell of the 8 around it (not across a cut-off line). Before, such manholes (often in streets whose cell centre fell into a house) had no surface and their overflow stayed ponded on the node, so square and unstructured results of the same model differed (user model: 98 of 593 manholes uncoupled on the square grid, 10 on the unstructured mesh). Cells left out for missing DEM data are not handled this way. Create Meshes reports the number of such manholes; a run with an older square mesh that has cells removed by buildings asks to rebuild the mesh (gen 2). Test (demo model, 100 ft cells, 2,500 buildings VOID): 128 cells removed, 54 manholes coupled to a neighbour cell (588 coupled in all), run completes.
