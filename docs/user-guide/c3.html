Create, open and save models

An Avaris2 CS model is an .inp file in the EPA SWMM 5 format. Avaris2 CS opens models written by EPA SWMM 5.x, Avaris CS, Avaris DS and other programs that use this format, and saves them so that these programs can still read them.

Commands

CommandWhereWhat it does
NewProject ▸ File ▸ New, Ctrl+NStarts an empty model with the default options and units.
OpenProject ▸ File ▸ Open, Ctrl+OOpens an .inp file. Large files are read in the background with a progress bar.
Save / Save AsQuick-access toolbar, Ctrl+S, Ctrl+Shift+SWrites the .inp and the files that go with it.
CloseProject ▸ File ▸ CloseCloses the model. If there are unsaved changes, you are asked whether to save them.

Files that belong to a model

To stay compatible with other programs, Avaris2 CS never writes unknown sections into the .inp file. It stores its extra information in comment lines starting with ;;@OSEM, which other programs ignore, or in files next to the model:

FileContents
Model.inpThe model.
Model.prjThe coordinate system of the map. It takes priority over the Avaris DS project file.
Model.iniThe Avaris DS project file: coordinate system, layers and 2D settings. Avaris2 CS reads it when you open a model created in Avaris DS.
Model.flags.jsonFlag panel settings: parameters, colours and custom flags.
Model.mesh2d.jsonThe 2D surface mesh.
Model.osemhist.jsonThe change history.
Model_Results\One set of files per simulation run: .inp, .rpt (status report), .out (binary results) and .json (run summary). 1D-2D runs use .finp, .frpt and .fout.
Tip:

Copy or archive the whole model folder rather than the .inp file alone, so the coordinate system, flags, mesh, history and results move with the model.

Database: runs and results

The Database tab, at the bottom of the left pane, lists the base model and every simulation run made from it, with its date, run time, units and continuity errors.

  • Every run has a name that you choose when you start it. Running again under the same name replaces that run; a new name keeps the earlier results.
  • Click a run to load its results onto the map, into the report and into graphs.
  • Right-click a run for Open Results, View Report, Add to Comparison (Scenario) (adds it to the graph windows as an extra run), Rename…, Show in Explorer and Delete. Right-click the base model to run a simulation, to close the results (Base Model Only) or to open another model.

Scenarios: runs of a model

In Avaris2 CS a scenario is a named run of the model. Each run keeps its own results, so you can change the model, run it under a new name and compare the runs at any time.

Create scenarios

  1. Run the existing system first, for example under the name Existing 10yr (Simulation ▸ Run, see Run a simulation).
  2. Change the model: larger pipes, a new storage tank, another design storm, different pump settings.
  3. Run again under a new name, for example Upgrade phase 1. A new name keeps the earlier results; using an existing name replaces that run.
  4. Repeat for every option. All runs are listed in the Database pane with their date, run type (1D, 1D-2D, coupled) and run time.

Compare scenarios

Open Simulation ▸ Analysis ▸ Comparison and choose the two runs in Base and Compare; see Scenario comparison. While the comparison is open, graph windows show exactly these two runs.

Tip:

Write a short description for each run in the Run dialog (for example pipes 30 % larger in Main Street). It is shown in the Database pane and helps you remember what changed.

Note:

To keep a variant of the model itself (not only its results), save a copy with Save As before you change it. Versions before 2.6.8 had a separate Scenarios panel on the Project tab; it was replaced by named runs and the Comparison view.

Add GIS data (Catalog)

The Catalog pane (Project ▸ Import, or the Catalog tab on the right) works like the ArcGIS Pro Catalog. Browse folders, then double-click a file or drag it onto the map to add it as a layer.

Supported formats

TypeFormats
VectorShapefile (also zipped), GeoJSON, KML/KMZ, GPX, DXF, CSV/TXT with X/Y columns, Esri File Geodatabase feature classes.
RasterGeoTIFF, images with a world file, ESRI ASCII grid.

Layers with a .prj file, or with a coordinate system stored inside the file, are reprojected to the map's coordinate system as they are added.

Import GIS data into the network

To turn GIS features into model objects, right-click an added layer and choose Import into Network…, or use Project ▸ Import.

  • Points become junctions, outfalls, storages or dividers.
  • Lines become conduits. Their ends snap to the nearest nodes within a tolerance, and missing nodes are created.
  • Polygons become subcatchments.

You map the GIS fields to model fields (ID, invert, rim, diameter, roughness, outlet…). Common field names are recognised automatically.

Coordinate systems and basemaps

A model needs a coordinate system before Avaris2 CS can draw an online basemap under it or reproject GIS layers onto it.

Set the coordinate system

  1. In the Layer View, click the Basemap warning (No coordinate system – click to set), or right-click the basemap and choose Coordinate System….
  2. Choose a preset, for example State Plane or Michigan GeoRef. Alternatively, paste the WKT or load a .prj file.
  3. Check the line below the text box. It shows where the centre of the model would fall, in latitude and longitude, with a link that opens the location in OpenStreetMap. A red ✗ means the model would land far from the origin of the projection, which usually indicates a wrong system or the wrong units (feet or metres).
  4. Click OK. The coordinate system is saved as Model.prj.

Supported projections are geographic coordinates, Transverse Mercator (UTM and State Plane TM zones), Lambert Conformal Conic with one or two standard parallels, Hotine Oblique Mercator (variants A and B), Mercator and Web Mercator. Units can be metres, feet or US survey feet, in WKT1 (ESRI .prj) or WKT2 format.

Basemap in the wrong place?

The most common cause is a .prj file that does not belong to the model, for example a UTM zone attached to a State Plane model. Open the coordinate system dialog, check the lat/lon of the model centre, and choose the correct system.

Basemaps

Right-click the Basemap layer to choose OpenTopoMap or OpenStreetMap; double-click it to set its transparency in Symbology. Map tiles are downloaded while you work and kept in a cache on your computer, so areas you have viewed also show without internet.

To prepare for working offline, for example on site, right-click the Basemap layer and choose Download for Offline Use…. Pick the level of detail; the dialog shows how many tiles that takes. The tiles covering the model area and a margin around it are then saved. Cached tiles are refreshed after 30 days when you are online.

Convert the model's coordinates

Tools ▸ Spatial Reference ▸ Convert Coordinates converts every node, vertex, polygon and rain gage from one coordinate system to another, for example from a local grid to State Plane. Use Test to check a point before converting. No datum shift is applied: NAD83 and WGS84 are treated as the same.

Attribute tables

An attribute table shows every object of one layer in a grid: network objects (junctions, conduits, subcatchments…), 2D mesh cells, or the features of an added GIS layer such as a Shapefile, GeoJSON, KML or File Geodatabase layer.

Open a table

  • Click Attribute Table above the Layer View and choose a layer. Added GIS layers are listed at the end.
  • Right-click a layer and choose Attribute Table.
  • In an open table, pick another layer from the list at the top left.

Work with the table

  • Sort: click a column header.
  • Statistics, Field Calculator, Colour Map by This Field: right-click a column header.
  • Filter: type part of an ID. For GIS layers, the filter searches every field.
  • Select: click a row; Ctrl+click adds a row and Shift+click selects a range. The selection is shared with the map; for GIS layers, the selected features are highlighted in cyan.
  • Edit: double-click a cell. Every edit can be undone.
  • Use Select All, Invert, Clear, Selected only and Zoom to Selected to manage the selection.
  • Copy and Paste exchange rows with Excel as tab-separated text. Paste needs a header row and the object ID in the first column.
  • Export CSV saves the rows that are currently shown.
Note:

Edits to an added GIS layer change it in memory only. Right-click the layer and choose Export as Shapefile… to save them.

Select by Attribute

Select by Attribute selects the objects that match a condition written in the expression language, for example:

rptMaxCapacity >= 1 and diam >= 0.6
type = 'CONDUIT' and slope < 0.1
name like 'J_5%'

Choose Create a new selection, Add to current selection, Remove from current selection or Select from current selection.

Export

The Export pane (Project ▸ Export) writes network objects with their attributes and results to:

  • Shapefile;
  • Esri File Geodatabase;
  • CSV.
  • Content:
    • Object attributes only;
    • Statistics: maxima and other summary results of the loaded run;
    • Snapshot Time: results at the current time step;
    • Selected Time Range.
  • Destination folder and file name prefix. One file, or one feature class, is written per object type.
  • Options: export only the selected objects, and choose which object types to export.

Graphs, profiles, report tables and the comparison table each have their own Export CSV or Save PNG buttons.

Units

The flow units of a model also decide the unit system of every other value.

Flow unitsSystemLengthVelocityRainfall
CFS, GPM, MGDUSftft/sin
CMS, LPS, MLDSImm/smm

To change the units, click Flow Units in the status bar or use Simulation Options. Avaris2 CS asks whether to:

  • Keep values: only the unit label changes and every number stays as it is, or
  • Convert values: every value of the model is converted to the new units (elevations, depths, lengths, diameters, areas, rainfall, curves and so on).

Flag thresholds follow the units automatically.

Tools ▸ Utilities ▸ Unit Converter converts single values of flow, length, area, volume, velocity, rainfall intensity and pressure between units.
