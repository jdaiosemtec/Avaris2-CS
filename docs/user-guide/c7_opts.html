Options: General

The General tab sets the units, the routing and infiltration methods and which process models take part in the run. Open it with Simulation ▸ Setup ▸ Options, or in the Parameter View with Options ▸ Simulation Options. The values are stored in the [OPTIONS] section of the .inp file; clicking OK applies all changes of the dialog as one undo step.

OptionMeaning
Flow UnitsCFS, GPM, MGD, CMS, LPS or MLD. The flow units also set the unit system of the whole model: CFS, GPM and MGD use US units (ft), CMS, LPS and MLD use SI units (m). A new value is not simply written into the file: after OK the same units switch as in the status bar opens and asks whether the values of the model are converted to the new units.
Routing ModelHow flow is carried through the network:
  • STEADY – steady flow: the inflow at the upstream end of each conduit is passed straight to the downstream end in every time step, without delay, storage or backwater.
  • KINWAVE – kinematic wave: the continuity equation with a simplified momentum equation (water surface slope equal to the conduit slope). Flow is attenuated and delayed, but backwater, flow reversal, pressurised flow and looped networks are not represented. Shown when the file has no routing option.
  • DYNWAVE – dynamic wave: the full one-dimensional Saint-Venant equations, solved together for conduits and nodes. Represents backwater, storage in the pipes, flow reversal, surcharge and pressurised flow, and looped and branched networks. Needs a short routing step; its settings are on the Dynamic Wave tab.
Infiltration ModelHow infiltration into the pervious area of the subcatchments is computed: HORTON, MODIFIED_HORTON, GREEN_AMPT, MODIFIED_GREEN_AMPT or CURVE_NUMBER. The parameters each subcatchment needs depend on this choice (Horton: maximum and minimum rate, decay constant, drying time; Green-Ampt: suction head, conductivity, initial deficit; Curve Number: curve number and drying time). Default HORTON.
Link OffsetsHow the inlet and outlet offsets of links are entered. DEPTH (default): height of the link invert above the invert of its node. ELEVATION: absolute elevation of the link invert.
Minimum Conduit Slope (%)Smallest slope used for any conduit, in percent; a conduit with a smaller computed slope uses this value instead. 0 (default) means no minimum is applied. The engine accepts values from 0 to below 100.
Allow PondingYES: water above the top of a node is stored in a pond over the node (using the node's ponded area) and returns to the network when there is room again. NO (default): water above the top of the node leaves the system as flooding and is lost.
Skip Steady StateYES: during periods in which the flows hardly change (within the steady-state tolerances on the Time Steps tab) the routing calculation is skipped and the previous flows are kept, which shortens long dry-weather periods. Default NO.
Process models
Ignore Rainfall/RunoffYES: rainfall, snowmelt and runoff from subcatchments are not computed; the network receives only the other inflows (dry weather, direct inflows, RDII, interface files).
Ignore SnowmeltYES: snowpacks and snowmelt are not computed, even if the model has snow data.
Ignore GroundwaterYES: the groundwater of the subcatchments and its flow to the network are not computed.
Ignore RDIIYES: rainfall-dependent infiltration/inflow (unit hydrographs assigned to nodes) is not added.
Ignore Flow RoutingYES: only runoff (and the processes above) is computed; no flow is routed through the network.
Ignore Water QualityYES: pollutant buildup, washoff and transport are not computed, even if the model has pollutants.

All Ignore … options default to NO. An Ignore … option left at NO is not written to the .inp file unless the file already contained it.

Recommended settings

  • Use DYNWAVE for networks with backwater, surcharge, loops, pumps or storage; KINWAVE and STEADY only for simple dendritic networks or quick runoff studies.
  • Change the flow units with the conversion offered after OK, so that lengths, depths and elevations stay consistent with the unit system.
  • Use the Ignore … options to switch off processes for a test run instead of deleting data from the model.

Options: Dates

The Dates tab sets the simulated period, the start of reporting and the dates used for pollutant buildup. Open it with Simulation ▸ Setup ▸ Options (or Parameter View ▸ Options ▸ Simulation Options) and click the Dates tab. Dates are entered as MM/DD/YYYY and times as HH:MM:SS, as the note on the tab says.

OptionMeaning
Start Analysis DateDate on which the simulation begins. Shown as 01/01/2026 when the file has none.
Start Analysis TimeTime of day at which the simulation begins (default 00:00:00).
Start Reporting DateDate from which results are written to the results file and the report. Defaults to the start analysis date. Reporting can start later than the analysis, for example to leave out a warm-up period.
Start Reporting TimeTime of day at which reporting starts (defaults to the start analysis time).
End Analysis DateDate on which the simulation ends (defaults to the start analysis date).
End Analysis TimeTime of day at which the simulation ends (default 06:00:00).
Street Sweeping Start (MM/DD)First day of the year on which street sweeping is applied to the land uses (default 01/01). Only affects water quality.
Street Sweeping End (MM/DD)Last day of the year on which street sweeping is applied (default 12/31).
Antecedent Dry DaysNumber of days without rain before the start of the simulation (default 0). Used to compute the initial pollutant buildup on the subcatchments.

When you click OK, the start analysis date, end analysis date and start reporting date are checked. An invalid date is reported (for example Invalid date for END_DATE) and the options are not changed.

Recommended settings

  • Make the analysis period long enough for the network to drain after the storm, so that the continuity errors and peak values are complete.
  • When the model starts dry and needs time to fill (for example base flow in a large network), start reporting after that warm-up period, or start from a hot start file (Files).

Options: Time Steps

The Time Steps tab sets how often results are saved and the computational steps of runoff, routing and control rules. Open it with Simulation ▸ Setup ▸ Options (or Parameter View ▸ Options ▸ Simulation Options) and click Time Steps.

OptionMeaning
Reporting Step (H:M:S)Interval at which results are saved to the results file (default 00:15:00). It decides the number of time steps in the results, which you see in play mode, graphs and tables; peak values in the statistics are still taken from every routing step.
Runoff Wet StepTime step for computing runoff from the subcatchments during rainfall or while water is still ponded on the surface (default 00:05:00, H:M:S).
Runoff Dry StepTime step for computing runoff in dry periods without rainfall or ponded water (default 01:00:00, H:M:S). It should not be shorter than the wet step.
Routing Step (H:M:S or sec)Time step for routing flow through the network, entered as H:M:S or as decimal seconds (default 0:00:20 = 20 s). With dynamic wave and a variable step (Dynamic Wave tab) this is the largest step allowed.
Control Rule StepInterval at which the control rules are evaluated (H:M:S). 00:00:00 (default) evaluates them in every routing step.
Steady State System Flow Tol. (%)Used with Skip Steady State (General): the system is treated as steady only while the difference between total system inflow and outflow is below this percentage (default 5).
Steady State Lateral Flow Tol. (%)Used with Skip Steady State: the system is treated as steady only while the change in lateral inflow at every node from one step to the next is below this percentage (default 5).

Recommended settings

  • A reporting step of 15 minutes is a good compromise for most storm events. Shorter steps give smoother hydrographs and animations but larger results files.
  • Do not set the reporting step shorter than the routing step.
  • For dynamic wave, use the variable step (Dynamic Wave tab) so that the routing step is only the upper limit.

Options: Dynamic Wave

The Dynamic Wave tab controls the numerical solution of dynamic-wave routing. The settings have an effect only when the Routing Model on the General tab is DYNWAVE. Open it with Simulation ▸ Setup ▸ Options (or Parameter View ▸ Options ▸ Simulation Options) and click Dynamic Wave. In each time step the Avaris engine computes the conduit flows and node heads in repeated iterations until the heads change less than the head tolerance; the settings below control these iterations and the length of the step.

OptionMeaning
Inertial TermsHow much the inertial (local and convective acceleration) terms of the momentum equation are damped. The list shows the damping level written to the .inp file (INERTIAL_DAMPING):
  • PARTIAL (default) – the inertial terms are reduced as the flow approaches critical (Froude number 1) and dropped for supercritical flow. This keeps the solution stable at transitions between sub- and supercritical flow.
  • FULL – full damping: the inertial terms are ignored everywhere (a diffusion-wave solution). Most stable, least exact for fast-changing flows.
  • NONE – no damping: the inertial terms are kept in full.
In a surcharged closed conduit the engine always uses full damping.
Normal Flow CriterionWhen the flow in a conduit is limited to normal flow (the Manning flow at the upstream depth):
  • BOTH (default) – when the water surface slope is less than the conduit slope, or the Froude number at the upstream end is 1 or more.
  • SLOPE – only when the water surface slope is less than the conduit slope.
  • FROUDE – only when the Froude number at the upstream end is 1 or more.
The limit applies only while the conduit is not full.
Force Main EquationFriction equation for conduits with a force-main cross-section when they flow full: H-W (Hazen-Williams, default) or D-W (Darcy-Weisbach). The roughness entered for force mains must match the equation (a C-factor for H-W, a roughness height for D-W). When partly full, force mains use the Manning equation.
Surcharge MethodHow surcharged (pressurised) flow is computed:
  • EXTRAN (default) – when a node is surcharged it has no storage; its head is found from the balance of the flows entering and leaving it.
  • SLOT – a narrow Preissmann slot is added on top of closed conduits, so that pressurised flow is computed with the same open-channel equations. Often gives smoother transitions between free-surface and pressurised flow.
EXTRAN is not written to the .inp file unless the file already contained a surcharge method.
Variable Step Safety Factor (0 = off)When above 0, the routing step is recomputed in every step from the Courant condition of the conduits (and the rate of change of the node depths) and multiplied by this factor; it is never longer than the Routing Step. 0 uses the fixed routing step. Default 0.75; the engine accepts 0 to 2.
Minimum Variable Step (sec)Smallest step the variable step may take, in seconds (default 0.5). The engine limits it to between 0.001 s and the routing step.
Conduit Lengthening Step (sec)When above 0, conduits so short that a wave passes through them in less than this time (or the routing step, if that is shorter) are artificially lengthened for the computation, with their roughness adjusted to compensate. This relaxes the Courant condition so that longer steps can be used. 0 (default) = no lengthening.
Minimum Nodal Surface AreaSmallest surface area given to a node when its depth is updated, in ft² (US units) or m² (SI units). Prevents very small manhole areas from making the node depths unstable. Default 12.566 (the area of a 4 ft diameter manhole); 0 also uses 12.566 ft².
Maximum Trials per StepMaximum number of iterations per time step to reach convergence of the node heads (default 8; 0 also uses 8). If the heads have not converged after this number, the step is counted as not converging and the engine continues with the last values.
Head Convergence ToleranceThe iterations of a step stop when the head at every node changes by less than this value between two iterations, in ft (US units) or m (SI units). Default 0.005; 0 also uses 0.005 ft.
Note:

The minimum nodal surface area and the head tolerance are in the length units of the model. When the model file has no values, the dialog shows the engine defaults in the model units: 12.566 ft² and 0.005 ft in a US-units model, 1.167 m² and 0.0015 m in an SI model. Changing the Flow Units between US and SI converts both values.

Recommended settings

  • The defaults (PARTIAL, BOTH, H-W, EXTRAN, safety factor 0.75, minimum step 0.5 s, 8 trials, tolerance 0.005) are the engine's own defaults and a sound starting point.
  • When many steps do not converge, look at Convergence diagnostics first, then consider a shorter routing step or a lower under-relaxation factor (Avaris Engine).
  • Compare the hydrographs before and after any change of these settings to make sure the results did not change materially.

Options: Files

The Files tab lists the interface files of the model: files that a run reads at its start or writes during the run, stored in the [FILES] section of the .inp file. Open it with Simulation ▸ Setup ▸ Options and the Files tab, or in the Parameter View with Options ▸ Interface Files (hot start, rainfall), which opens the dialog on this tab. The Parameter View shows the number of files after the entry.

Interface Files list

Each line shows the usage (Use or Save), the file type and the file path, for example Use Hotstart hs.hsf. Above the list:

OptionMeaning
+Adds a file (initially Use Hotstart without a path) and selects it, ready for its path.
−Removes the selected file from the list.
Clear AllRemoves all files from the list, after confirmation.

File Property

The fields below the list edit the selected line.

OptionMeaning
File Type
  • Hotstart – the state of the model (such as node depths and link flows) at the end of a run. Save writes the state at the end of the run; Use starts a run from that state instead of from a dry network. Extension .hsf.
  • Rainfall – binary rainfall interface file with the rain gage data of a run (extension .dat or .rff).
  • Runoff – binary runoff interface file with the runoff results of a run (extension .rof or .dat); with Use, a later run reads the runoff instead of computing it.
  • RDII – rainfall-dependent infiltration/inflow at the nodes (extension .rdi, .txt or .dat).
  • Inflows – a routing interface file with inflow hydrographs (and pollutographs) for nodes of this model, usually the Outflows file of an upstream model (.txt or .dat).
  • Outflows – a routing interface file with the outflows at the outfalls of this model, to be used as Inflows of a downstream model (.txt or .dat).
Usage TypeUse = read the file at the start of the run (for example a hot start file with the initial state). Save = write it during the run (for example a hot start file of the state at the end, for the next run).
File PathType the file name or click …. For Save the button opens a save dialog (suggested name hotstart.hsf or <type>.<ext>), for Use an open dialog; both filter by the extensions above. A file name without a folder is in the model folder, and paths are stored relative to the model folder, so the model can be moved with its files.

When you click OK, lines without a file name are left out (a message says so). Comment lines and other lines of the [FILES] section are kept. The change is one undo step.

Rain data files:

Rainfall, Runoff and RDII files on this tab are binary interface files written by Save of an earlier run. A text file of rain data is linked in the Rain Gage Editor (Data Source FILE), not here. When a Use Rainfall or Use Runoff line names the data file of a rain gage, the line is shown in red with "⚠ rain gage data file" and a warning explains that the run would stop with a file format error; remove that line.

Before each run, files the model needs that are missing or cannot be used are listed; see Run Status and status report.

Recommended settings

  • To avoid a long warm-up in every run, run the model once with Save Hotstart, then use that file with Use Hotstart in the following runs.
  • Keep interface files in the model folder (or a folder below it), so that the relative paths stay valid when the model is copied.

Options: Avaris Engine

The Avaris Engine tab holds the settings that the Avaris engine adds to the standard options: parallel computation, the relaxation of the dynamic-wave iterations, the nonconvergence report and the size of the report file. Open it with Simulation ▸ Setup ▸ Options (or Parameter View ▸ Options ▸ Simulation Options) and click Avaris Engine.

OptionMeaning
Number of Threads (0 = all cores)Number of processor threads used for dynamic-wave routing (default 1). Conduit flows and node depths are solved in parallel (OpenMP); results are identical for any number of threads. 0 uses all logical processors; a larger number than the computer has is reduced to that. The engine uses 1 thread when the model has fewer than 4 links per thread. Scenarios running at the same time always use 1 thread each.
Detect & RecommendScans the processors of this computer and shows:
  • This computer: processor model, number of cores, logical processors and memory;
  • Maximum recommended: logical processors − 1 (one is left for Avaris2 CS and Windows);
  • For this model: the number of nodes and links (including the 2D cells and surface links when 2D flooding is on) and the recommended number of threads, with a Use N button that enters it.
The recommendation depends on the number of links: 1 thread below 1,000 links, 2 below 3,000, 4 below 10,000, 6 below 30,000 and 8 above, but never more than the maximum recommended, the number of physical cores, or one thread per 4 links.
Under-Relaxation Factor (0.1 - 1.0)Weight given to the new iterate in the dynamic-wave Picard iterations; the standard value is 0.5. Lower values damp oscillation at hard-to-converge nodes; higher values converge faster on well-behaved networks. A value outside 0.1–1.0 is refused when you click OK. The value 0.5 is not written to the .inp file unless the file already contained it.
Nonconverging Nodes Listed in ReportLength of the "Most Frequent Nonconverging Nodes" list in the report file (default 100; the standard report lists 5; maximum 500). This list feeds Convergence diagnostics. The value 100 is not written to the file unless it already contained it.
Write time-series tables to report fileOff by default: results are read from the binary results file, which keeps the report file small for large models. Switch it on to have the time-series tables written into the report as well. This setting belongs to the current Avaris2 CS session, not to the .inp file.

Recommended settings

  • Click Detect & Recommend and Use N instead of entering 0: small models gain nothing from many threads, and using all logical processors leaves none for the user interface.
  • Keep the under-relaxation factor at 0.5; lower it (for example to 0.3) only when convergence diagnostics show oscillating nodes.
  • Leave Write time-series tables to report file off for large models.

Run Status and status report

A run goes through four dialogs: checks before the run, the Run Simulation dialog with the run name, the progress dialog, and finally Run Status with the continuity errors, convergence and warnings. Start a run with Simulation ▸ Run ▸ Run or F5 (see Run a simulation).

Checks before the run

  • A model without nodes is not run.
  • The quick checks of Validate Model are run; any problems (up to 15 are shown, with the total) are listed with the choice Run anyway or cancel.
  • With 2D flooding, a mesh made by an older version of Avaris2 CS offers Run with Old Mesh or Rebuild Mesh, then Run; if no mesh exists yet you can choose Create Meshes or Run 1D only.
  • Files the model uses but that are not found or cannot be used (interface files, rain gage and time-series files) are listed with their full path. Open Interface Files opens the Files tab. If all missing files are optional interface files, Run Without Them leaves them out of this run only (a run without its hot start file starts dry).

Run Simulation dialog

OptionMeaning
Simulation nameName of the run; its files are saved under this name in the <model>_Results folder next to the model and listed in the Database panel. The suggestion is the last name used, or Run_YYYYMMDD_HHMM. Only letters, digits, spaces and _ - . ( ) are allowed. A new name keeps the earlier results; an existing name replaces them after confirmation.
DescriptionOptional text saved with the run, for example "100-yr storm, pumps upgraded".
RunShown only when the model has been partitioned: Whole model or Coupled parallel – N sub-models, M cut points, with a note on the expected speed. The coupled option is unavailable without the High Performance Simulation edition, when the model changed after it was partitioned, or when sub-model files are missing; a note says which. See Coupled parallel simulation.
Existing results (click to reuse a name)The latest 12 runs of the model with date and type. Clicking one copies its name and description into the fields.

If the model has not been saved, a note says that the results go to a temporary folder; save the model to keep its results in the Database. Click Run to start.

Progress dialog

The dialog Running Simulation - <name> shows what is being run – for example Avaris engine: DYNWAVE routing, 1520 nodes, 1610 links, plus the number of 2D cells and surface links for a 1D-2D run – and a progress bar with the percentage, the elapsed time and the estimated remaining time. Stop cancels the run; the status bar then shows Simulation stopped by user. and no results are loaded.

Run Status - Errors

If the engine reports errors, Run Status - Errors says The run was not successful. and lists up to 40 error lines from the report (or the engine exit code). View Report opens the report file; Close closes the dialog.

Run Status

After a successful run the results are loaded and Run Status opens. Its first line is green, Run was successful., when both continuity errors are below 5 %; otherwise it reads Run completed - continuity errors are high, check the report.

LineMeaning
Run timeWall-clock time of the run in seconds.
Runoff continuity errorPercentage difference in the runoff mass balance: rainfall and initial storage against infiltration, evaporation, runoff and final storage on the subcatchments.
Flow routing continuity errorPercentage difference in the network mass balance: all inflows and initial stored volume against outflows, flooding, losses and final stored volume. A high value points to numerical problems in the routing (often too long a routing step or nonconverging nodes).
WarningsNumber of WARNING lines in the report. Up to 20 of them are listed below the table.
% of steps not convergingFrom the routing time step summary of the report (dynamic wave): the share of routing steps in which at least one node did not reach the head tolerance within the maximum trials.
Average iterations per stepFrom the same summary: the mean number of iterations needed per routing step.
Worst nonconverging nodeThe first node of the "Most Frequent Nonconverging Nodes" list, with its percentage of steps not converged.

The last three lines appear only when the report contains them. The buttons are:

  • Convergence Diagnostics – opens the Nonconvergence Diagnostics view (Convergence diagnostics).
  • View Report – opens the report of the run.
  • OK – closes the dialog; the results stay loaded.

After a coupled parallel run the dialog also shows the Run mode (number of sub-models and cut 2D links), the run time with the engine time, a note that the sub-model results were merged into one run of the master model, and a Sub-models table (nodes + 2D cells, computing and waiting seconds, core) naming the sub-model that computes longest. It has only View Report and OK.

Every run, successful or not, is recorded in the Database with its name, description, date, type (1D, 1D-2D or coupled), run time, continuity errors, number of warnings and share of steps not converging.

Recommended checks

  • Continuity errors below 5 % give the green message; higher values mean the report should be checked.
  • Read the warnings; they often name objects with doubtful data.
  • When steps do not converge, open Convergence Diagnostics and follow the tips in Run a simulation.
