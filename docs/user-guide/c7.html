Simulation options

Simulation ▸ Setup ▸ Options opens the Simulation Options dialog. Its tabs follow the [OPTIONS] section of the .inp file, plus tabs for the Avaris engine, object defaults and 2D flooding.

General

On this tab you set:

  • flow units;
  • routing model: Steady, Kinematic Wave or Dynamic Wave;
  • infiltration model: Horton, Modified Horton, Green-Ampt, Modified Green-Ampt or Curve Number;
  • link offsets (depth or elevation);
  • minimum conduit slope, ponding and skipping steady-state periods;
  • which process models to ignore: rainfall/runoff, snowmelt, groundwater, RDII, flow routing or water quality.

Dates and time steps

Set the start and end of the analysis, the start of reporting, the street-sweeping period and the antecedent dry days. Then set the reporting step, the wet-weather and dry-weather runoff steps, the routing step, the control rule step and the steady-state tolerances.

Note:

The reporting step decides how many time steps are saved in the results file. It also sets the accuracy of the time functions used by themes and flags: 15 minutes is a good compromise for most storm events.

Dynamic Wave

The dynamic-wave settings are:

  • inertial terms;
  • normal flow criterion;
  • force main equation;
  • surcharge method (EXTRAN or SLOT);
  • variable step safety factor;
  • minimum variable step;
  • conduit lengthening step;
  • minimum nodal surface area;
  • maximum trials per step;
  • head convergence tolerance.

Avaris Engine

SettingMeaning
Number of ThreadsConduit flows and node depths are solved in parallel with OpenMP; 0 uses all cores. Detect & Recommend proposes a value for this computer. Results are identical for any number of threads. Models with fewer than 4 links per thread run on one thread.
Under-Relaxation FactorThe weight given to the new value in each dynamic-wave iteration (0.1–1.0). The standard value is 0.5. Lower values damp oscillation at hard-to-converge nodes; higher values converge faster on well-behaved networks.
Nonconverging Nodes Listed in ReportLength of the "Most Frequent Nonconverging Nodes" list in the report. The standard report lists 5; Avaris lists up to 500.
Write time-series tables to report fileOff by default. Results are read from the binary file, which keeps the report small for large models.

Object Defaults

Default values for new nodes, conduits and subcatchments: depths, diameter, roughness, length, area, width, imperviousness and slope. They are saved with your Avaris2 CS settings, not in the model.

2D Flood

The settings of the 1D-2D flood module. See Set up a 2D model.

Run a simulation

  1. Click Simulation ▸ Run ▸ Run or press F5. Avaris2 CS first runs the quick checks of Validate Model and shows any problems, with the choice to run anyway.
  2. Enter a simulation name and an optional description. Click an existing name to reuse it, which replaces that run.
  3. Watch the progress. Click Stop to cancel. If 2D flooding is enabled but no mesh exists yet, you can create the mesh first or run the 1D model only.

When the run finishes, the results are loaded automatically. The status bar shows the number of reporting steps, and a summary lists the continuity errors, flooding and warnings.

Several runs at the same time

From the Scenarios panel, Run Selected & Compare runs several scenarios in parallel, each with its own engine process, and then compares them. A panel shows the progress of each run, and Stop All cancels them.

Convergence diagnostics

After a dynamic-wave run, Simulation ▸ Results ▸ Convergence lists the nodes where the engine most often failed to converge, with the share of steps not converged and any orifices next to them. It also shows the routing time step summary from the report.

Color Map by Nonconvergence shows on the map where the problem is concentrated, and Select All Listed selects those nodes.

Reducing non-convergence
  • Convert problem orifices to equivalent conduits (Orifice to Conduit).
  • Lower the under-relaxation factor, for example to 0.3.
  • Check very short conduits and large steps in invert levels.
  • Re-run and compare the hydrographs to confirm that the results did not change materially.

2D flood modelling overview

🔒 Avaris2 CS 1D-2D

The 2D flood module covers the ground surface with a mesh of square cells, coupled to the manholes of the pipe network. Water that surcharges out of a manhole flows over the surface, following the terrain, and can re-enter the network downstream.

How it works

  • A 2D boundary polygon defines the area. Its attributes set the cell size (length) and the Manning roughness of the ground (roughness).
  • The cells take their ground elevation from a DEM (GeoTIFF or ASCII grid).
  • Optional water front lines let surface water leave the model, for example at a river bank or coast. Cut-off lines block flow across walls and embankments, and exclusion polygons remove buildings and other areas without cells.
  • Every junction, storage unit or divider tagged Link2D is coupled to the cell it lies in.
  • The cells and the surface links between them are added to a copy of the model (.finp) and simulated together with the pipe network by the Avaris engine. The approach is compatible with Avaris DS, so models with 2D settings in the Avaris DS project file (.ini [2D]) are taken over automatically when you open them.

Set up a 2D model

  1. Open Simulation ▸ Options ▸ 2D Flood and tick Enable 1D-2D flood simulation.
  2. Choose the input layers:
    • 2D Boundary (polygon);
    • Digital Elevation Model;
    • optionally the Water Front, Cut-off Lines and Exclusion Polygons.
    Paths inside the model folder are stored as relative paths.
  3. Set the cell size and roughness, or leave them blank to use the boundary attributes.
  4. Set the Mesh Units:
    • MODEL, as in Avaris DS, uses the values as they are;
    • CONVERT converts them from the map units to the model units, for example a metre DEM in a US-units model.
  5. Tick Tag all nodes "Link2D" to couple every manhole, or tag selected nodes yourself.
  6. Click Simulation ▸ Setup ▸ Create Meshes. The mesh is saved as Model.mesh2d.json and appears as the 2D Meshes layer, coloured by ground elevation.
  7. Run the simulation. 1D-2D runs write .finp, .frpt and .fout files.
Note:

Rebuild the mesh after you change the boundary, DEM, cell size, exclusions or the Link2D tags.

2D results

After a 1D-2D run, the 2D Meshes layer can show:

VariableMeaning
Max. DepthGreatest water depth on each cell during the run.
Time Ponded (hr)Time the cell was deeper than the Flood Depth Threshold.
Time to Recede (hr)Time from the peak until the depth fell back below the threshold (to the end of the run if it never did).
Depth (current time)Depth at the current time step, while playing.
Water Surface Elev. (current time)Water level at the current time step, while playing.
Ground ElevationCell elevation from the DEM.

Double-click the 2D Meshes layer to choose the variable, the colour ramp (for example Flood Depth), the ranges and the transparency. Cells shallower than the first range are left uncoloured.

Hover over a cell to read its values. Click it for details and a depth graph. The mesh also has an attribute table, and it can be exported as a shapefile with its results from the layer's right-click menu.
